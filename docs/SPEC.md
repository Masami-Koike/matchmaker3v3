# MatchMaker 3v3 仕様書

## 1. 概要

### 1.1 アプリケーション名
**MatchMaker 3v3**

### 1.2 目的
3対3形式のスポーツ(バスケットボール、バレーボール、フットサル等)において、参加プレイヤーの組み合わせを公平かつ偏りなく自動生成するためのWebアプリケーション。

### 1.3 動作環境
- **形態**: 単一HTMLファイル(`index.html`、約28KB)
- **必要環境**: モダンWebブラウザ(Chrome / Safari / Edge / Firefox)
- **対応デバイス**: スマートフォン優先(最大幅 640px)、タブレット/PCでも閲覧可
- **iOS対応**: ホーム画面追加 (PWA風) に対応(`apple-mobile-web-app-*` メタタグ設定済)
- **オフライン**: ネットワーク不要(全処理クライアントサイド完結)
- **依存ライブラリ**: なし(Vanilla JS / HTML / CSS のみ)

### 1.4 データ保存
- ブラウザの **localStorage** にキー `matchmaker3v3_v1` で全状態を JSON シリアライズして保存。
- アプリ再起動後も状態が復元される。

---

## 2. 画面構成

ヘッダー + 3タブの単一ページアプリ。

| 画面ID | タブ表示名 | 役割 |
|--------|-----------|------|
| `page-players` | プレイヤー | プレイヤーの登録・出場可否切替・削除・試合数表示 |
| `page-match` | 組み合わせ | コート数設定、組み合わせ生成、最新ラウンドの表示 |
| `page-history` | 履歴 | 過去ラウンドの一覧表示 |

ヘッダー右側の `⋯` ボタンでボトムシート型メニューを開き、リセット操作を実行できる。

## 3. データモデル

すべてのデータは `state` オブジェクトに保持される。

```ts
state = {
  players: Player[],
  courtCount: number,    // 1〜20
  rounds: Round[],       // 先頭が最新
}

Player = {
  id: string,            // 内部ID(時刻+乱数で生成)
  name: string,          // 表示名(最大20文字)
  isActive: boolean,     // 出場対象かどうか
  gamesPlayed: number,   // 通算試合数
}

Round = {
  roundNumber: number,           // 1始まりの連番
  matches: Match[],              // 各コートの試合
  resting: PlayerRef[],          // このラウンドで休憩したプレイヤー
  timestamp: number,             // 生成時刻 (ms)
}

Match = {
  courtNumber: number,           // 1始まり
  teamA: PlayerRef[],            // 3名
  teamB: PlayerRef[],            // 3名
}

PlayerRef = { id: string, name: string }
```

## 4. 機能仕様

### 4.1 プレイヤー管理(プレイヤータブ)

#### 4.1.1 プレイヤー追加
- 入力欄に名前を入力 → `追加` ボタン または Enter キーで登録。
- 空白のみの名前は登録不可(前後空白は trim)。
- 最大20文字。
- 追加直後は `isActive = true`、`gamesPlayed = 0`。

#### 4.1.2 出場可否の切替
- 各プレイヤー左の丸チェック(✓)タップで `isActive` をトグル。
- 非アクティブ時は項目が薄く表示される(opacity 0.45)。
- 非アクティブのプレイヤーは組み合わせ生成の対象外となる。

#### 4.1.3 プレイヤー削除
- 右端の `✕` ボタンで削除。確認ダイアログあり。
- 過去ラウンド内のプレイヤー名は削除しても表示上は残る(`Round` 内に名前を保存しているため)。

#### 4.1.4 試合数バッジ
- 各プレイヤーに `〇 試合` のバッジを表示し、累計出場試合数を可視化。

#### 4.1.5 空状態
- プレイヤーが0名のときは `👥 プレイヤーを追加してください` を表示。

### 4.2 組み合わせ生成(組み合わせタブ)

#### 4.2.1 コート数設定
- 1〜20 の範囲で `−` `+` で増減。
- 出場対象人数が足りない場合は実使用コート数が自動的に減る(`min(courtCount, floor(active/6))`)。

#### 4.2.2 統計サマリー(3カラム)
- **出場対象**: `isActive = true` のプレイヤー数
- **使用コート**: 実際に試合を組めるコート数
- **休憩**: `出場対象 − 使用コート × 6`

#### 4.2.3 組み合わせ作成
- `組み合わせを作成` ボタンで以下のロジックを実行(詳細は §5)。
  1. 試合数が少ない順に出場者を選出(同数はランダム)。
  2. 過去のチームメイト/対戦履歴から偏りが最小になるチーム分けを探索。
  3. 各出場者の `gamesPlayed` を +1。
  4. ラウンドを `state.rounds` の先頭に追加。
- 使用コート数 < 1 のときボタンは無効。

#### 4.2.4 直前ラウンドの取消
- `直前のラウンドを取消` で最新ラウンドを削除し、関係者の `gamesPlayed` を -1(0未満にはしない)。
- 確認ダイアログあり。
- ラウンド番号の振り直しは行わない(欠番が出る)。

#### 4.2.5 最新ラウンド表示
- ラウンドタイトル(例: `最新ラウンド` / `Round 3 · 14:05`)。
- コートごとに `TEAM A` (水色) と `TEAM B` (ピンク) のメンバー3名ずつを表示、中央に `VS`。
- 休憩者がいれば下部に `休憩 (N名)` として一覧表示(区切りは ` / `)。

### 4.3 履歴(履歴タブ)
- 全ラウンドを **新しい順** に表示。
- 各ラウンドの形式は最新ラウンドと同じ(タイトルは `ラウンド N`)。
- ラウンドが0件のときは `📋 まだ履歴がありません` を表示。

### 4.4 メニュー(ボトムシート)
ヘッダー右上 `⋯` から開く。

| 項目 | 動作 |
|------|------|
| 試合数をリセット | 全員の `gamesPlayed = 0`、`rounds = []`。確認あり。 |
| 全データをリセット | プレイヤーを含む全 `state` を初期化。確認あり。 |
| キャンセル | シートを閉じる |

シート外タップでも閉じる。

## 5. マッチメイキングアルゴリズム

### 5.1 出場者の選出
1. アクティブプレイヤーを `gamesPlayed` 昇順でソート。
2. 同値はランダム順(`Math.random() - 0.5` による比較)。
3. 先頭 `usableCourts × 6` 名を出場、残りを休憩に割り当て。

### 5.2 ペア履歴の集計
全過去ラウンドを走査し、以下の Map を構築する。
- `teammate[(a,b)]`: 同じチーム(A or B)に属した回数。
- `opponent[(a,b)]`: 対戦相手として組み合わさった回数。

キーは ID 2つを昇順で `|` 結合した文字列。

### 5.3 6人 → A3 / B3 への分割(`bestSplit`)
- 6人中3人を選ぶ全 C(6,3) = 20 通りを総当たり。
- 各分割のスコア = `Σ teammate × 3 + Σ opponent × 2` + 微小ランダム。
- スコア最小の分割を採用。

### 5.4 複数コート割当(`assignToCourts`)
- 出場者を **シャッフル** → 6人ずつコートに分割 → 各コートで `bestSplit`。
- スコア最小の試行を採用。
- 試行回数: コートが1の場合は1回、複数の場合は **80回**。

### 5.5 設計の意図
- **チームメイト重複** は **対戦重複** より重く重み付け(× 3 vs × 2)し、「同じ味方ばかりになる」のを優先的に避ける。
- 微小ランダムを加えることで同点時のチーム固定を防止。
- 出場機会は `gamesPlayed` 昇順選出により均等化される。

## 7. セキュリティ / 堅牢性

### 7.1 XSS対策
- ラウンド表示において、プレイヤー名は HTML 文字列に直接埋め込まず、テンプレートで枠を生成後 `textContent` 経由で名前を流し込む二段階レンダリング (`renderRoundDOM`)。
- プレイヤー一覧でも `textContent` を使用。

### 7.2 入力バリデーション
- プレイヤー名: trim 後の空文字を拒否。
- コート数: 1〜20 にクランプ、ボタンの `disabled` 属性で UI 側でも抑制。
- localStorage 読み込み時: `players` が配列であること、`courtCount` が数値であること、`rounds` の存在を検証し、欠損時は安全なデフォルトに復旧。

### 7.3 例外処理
- `localStorage` の読み書きは try/catch で保護(プライベートモード等で利用不可な場合に備え `console.warn` でフォールバック)。

## 9. 既知の仕様/制約

- **ラウンド番号は再採番しない**: `undoLastRound` で削除しても以後の番号は連続しない可能性がある(削除直後は問題ないが、複数操作で欠番が生じる)。
- **試合数のリセットは履歴も消す**: 「試合数をリセット」は `gamesPlayed` だけでなく `rounds` も全削除する。
- **ストレージスキーマのバージョニング**: キーに `_v1` を含むのみで、マイグレーションロジックは未実装。スキーマ変更時は手動移行が必要。
- **同時編集**: 複数タブで開いた場合の同期は行われない(後から保存した側で上書き)。
- **エクスポート/共有機能は未実装**(画面確認のみ)。
